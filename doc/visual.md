# 《Ring Run》视觉与界面规范

## 1. Experience intent

玩家先感到“婚礼就差这枚戒指”的普通压力，再在四秒画线里感到路线聪明，最后因猫、扫地机器人或香槟瓶把婚戒当成自己的订婚戒而发笑。

一句话方向：在奶油婚礼请柬背面，用酒红蜡笔画一条救命路线，让带着玩家头像的天鹅绒戒指盒穿过编辑插画般的婚礼灾难。

## 2. Direction decision

1. **高级请柬应急图（采用）**：婚礼物件天然提供情绪支点；线路像人工批注，适合单笔手势和荒诞失败。
2. 儿童迷宫卡通（拒绝）：三秒可懂，但容易显得廉价，玩家头像像贴纸。
3. 写实酒店平面图（拒绝）：空间关系清楚，但图例和建筑细节会让普通用户读不懂。

## 3. Composition

- 顶部 12%：左 `RING EMERGENCY n/3`，右剩余路线；两者无卡片背景。
- 危险句位于顶部 16–22%，最多两行；不遮挡威胁运动范围。
- 起点位于左下 18% × 72%，目标位于右上 82% × 27%；三幕可以镜像，但起点与目标始终一眼可见。
- 动态威胁占中央 52% 主路径区；用淡金虚线显示其运动走廊，而不是说明文字。
- 结果纸带位于底部 18%，失败命中位置仍保持可见。

## 4. Visual system

- 纸面 `#f4e7c7`，瓶绿 `#183a32`，酒红 `#8d2738`，金箔 `#d4a83f`，钴蓝 `#315d91`，墨黑 `#171914`。
- 背景用低对比纸纤维、压花边框和两处金箔角花；禁止玻璃拟态、霓虹、老虎机光效。
- Display 使用紧凑高对比衬线；操作与数值用粗体无衬线，最小 12px；中文回退 PingFang SC。
- 戒指盒为深绿圆角方盒，金色边与奶油内衬；头像直径 36–44px，真实圆形裁切。
- 路线绘制态为 10px 酒红蜡笔 + 2px 奶油断续高光；锁定后为 12px 瓶绿缎带 + 2px 金边。

## 5. Scene language

- `THE CAT`：酒红猫爪从画外扫入，爪尖有四个奶油软垫；失败时一只爪趾戴金戒。
- `THE VACUUM`：钴蓝圆形机器人，金色状态灯和明确圆形碰撞轮廓；失败时戒指套在顶部传感器。
- `THE CHAMPAGNE`：深绿瓶、金箔标签但无文字；失败时戒指套在瓶颈，软木塞短促弹起。
- 目标依次是服务门、酒店电梯、花门戒台；用同一金色光圈表示，不用功能 Emoji。

## 6. State and feedback

| 状态 | 主要画面 | 反馈 |
|---|---|---|
| briefing | 起点、目标、危险走廊、单句指令 | 起点金圈低速脉冲 |
| drawing | 酒红湿线、剩余长度 | 同帧墨迹、吸附亮边 |
| locked | 路线变绿金缎带 | 140ms 扣合、目标闪光 |
| running | 戒指盒沿路、威胁运动 | 每 16% 路程金点闪烁 |
| success | 到达目标、威胁错过 | 绿色压花 `DELIVERED` |
| failure | 精确接触、荒诞归属末拍 | 酒红纸带与专属演出 |
| final | 玩家头像、总分、三枚通过印章 | 金箔花门从两侧合拢 |

## 7. Responsive and accessibility

- 390×844：保留完整请柬边框、中央运动走廊和底部纸带。
- 320×568：顶部字缩至 10px，危险句最多 36px 高，起点上移至 66%，结果纸带最高 116px；Canvas 使用 CSS 像素重算，不整体缩放 DOM。
- 按钮高 ≥48px；起点吸附半径 54px、目标 64px，触控容错大于视觉图形。
- 指令、路线状态和结果不只靠颜色；用线型、动效和文字共同表达。
- reduced-motion 取消纸张震动、金箔扫光和弹性，只保留位置变化与精确接触冻结。

## 8. Identity and asset rules

- 图像顺序：`?avatar_url=` → Aigram 当前玩家 `head_url` → `public/default-avatar.png`；图片失败也回退默认头像。
- 文字顺序：`?user_name=` → Aigram `data.name` → `AlterU`；长名字在戒指盒签条内 ellipsis。
- 玩家头像必须随戒指盒真实移动并参与碰撞，不能留在 HUD 角落。
- 正式海报由 Aigram transit 生成，画面包含真实西方婚礼现场、玩家头像戒指盒、酒红手绘路线和逼近猫爪；标题仅英文 `RING RUN`，禁止伪字、中文和界面截图。

## 9. Vertical-slice gate

- 第一幕必须在 390×844 与 320×568 验证：有效路线成功、故意穿过猫爪失败、未到目标提示、墨水耗尽、pointercancel 恢复。
- 真实画面能在三秒内复述为“从我的戒指盒画一条安全路线到右上角”。
- 猫爪运动走廊在绘制前可读；成功不是随机等待，失败接触点与路线相符。
- 第一幕通过后，才复制同一移动/路径合同扩展机器人和香槟，而不是提前写三套独立逻辑。
